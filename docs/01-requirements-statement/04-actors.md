# 👥 이해관계자 및 Actor

| Actor | 유형 | 시스템과의 관계 |
|---|---|---|
| **배치 스케줄러** | 외부 시스템 | 매일 정해진 시각에 정산 Job을 트리거한다. 트리거 방식은 🚧 미확정 |
| **관리자** | 사람 | 관리자 콘솔로 기사별·기간별 정산 내역을 조회한다. 대사 불일치를 확인하고 대응한다 |
| **결제 서버** | 외부 시스템 | 정산 배치가 전일 결제 내역을 조회하는 대상 |
| **원장 서버** | 외부 시스템 | 대사 검증 시 기사 미지급금 잔액을 조회하는 대상. 🚧 지급 분개 기록 대상이 될 수도 있다 |
| **기사** | 사람 (간접) | 정산 서버를 직접 호출하지 않는다. 문의 시 관리자가 조회 API로 답한다 — **이 시스템의 존재 이유** |
| **운영팀** | 사람 (간접) | 배치 실패·대사 불일치를 인지하고 대응한다 |

> 기사는 시스템을 직접 쓰지 않지만 요구사항의 출발점이다. "기사가 문의했을 때 답할 수 있는가"가 설계 판단의 기준선이다.

각 Actor가 어떤 유스케이스에 관여하는지는 [유스케이스 다이어그램](../03-use-case-diagram/index.html)에서 본다.
