# 🚧 미확정 항목

**아래는 아직 결정되지 않았다. 08.11(화) 중간 회의에서 확정한다.** 이 문서와 정의서·다이어그램에서 확정된 것처럼 서술하지 않는다.

| # | 항목 | 선택지 | 트레이드오프 | 영향 |
|---|---|---|---|---|
| U1 | **배치 트리거 방식** | (A) AWS EventBridge (B) Spring `@Scheduled` | (A) 스케줄러 서버 불필요, 배포 위치 결정에 종속 / (B) 서버가 상시 떠 있다면 훨씬 단순, 서버가 죽으면 배치도 안 돎 | `FR-B-09` |
| U2 | **결제 서버 장애 시 재시도 정책** | (A) 청크 단위 재시도 (B) Job 전체 재실행 (C) 다음 날 배치가 미처리분 흡수 | 서버 분리로 새로 생긴 문제다. 단일 서버였다면 DB 조회로 끝날 일이 이제 HTTP 실패 지점이 됐다 | `FR-B-10`, `NFR-04` |
| U3 | **Reader 페이지네이션** | (A) offset/limit (B) cursor (커서 기반) (C) 전건 일괄 | 건수가 많을 때 (A)는 뒤 페이지가 느려지고 (C)는 메모리를 먹는다. 결제 API 스펙과 함께 결정해야 한다 | `FR-B-11`, `IF-01` |
| U4 | **수수료율 20%** | (A) 상수 하드코딩 (B) 설정값(`application.properties`) (C) DB 테이블 | (A) 가장 단순, 변경 시 재배포 / (C) 요구에 없는 유연성 — 현 시점 과설계로 보인다 | `FR-B-03` |
| U5 | **대사 불일치 통지 수단** | (A) 로그만 (B) 조회 API 응답에 플래그 (C) 관리자 대시보드 배지 (D) SNS 알림 | (A)는 아무도 안 본다. (D)는 3주 안에 하기엔 부담 | `FR-R-03` |
| U6 | **대사 실패 시 CONFIRMED 보류 여부** | (A) 불일치면 `CONFIRMED`로 올리지 않고 보류 (B) 올리되 불일치를 기록 | (A)가 안전하지만 원장 서버가 잠깐 죽어도 정산이 확정되지 않는다. **금액 판단에 직접 영향** | `FR-R-04` |
| U7 | **`CONFIRMED` → `PAID` 전이 방식** | (A) API로 노출 (B) 배치 내부에서만 처리 | 실제 송금이 없으므로([§4.2](./03-scope.md)) 어느 쪽이든 데모는 가능하다 | `FR-S-02`, `UC-06` |
| U8 | **정산 확정 시 원장 지급 분개 기록** | (A) 기록한다 (B) 기록하지 않는다 | (A)를 택하면 정산 → 원장 쓰기 호출이 생겨 실패 보상 문제가 정산에도 옮겨온다 | `FR-S-03`, `IF-03` |
| U9 | **정산 내역서 보관 위치** | (A) Amazon S3 (B) Supabase Storage (C) 생성하지 않음 | DB를 Supabase로 옮긴 만큼 (B)도 후보다. (C)면 조회 API로 대체 | `FR-Q-03` |
| U10 | **서비스 경계를 넘는 FK** | (A) `settlement_items.trip_ids`가 `trips`를 FK 참조 (B) 참조 없이 ID만 보관 | (A)는 정산이 결제 테이블에 물리적으로 묶인다 — [§4.3 경계 규칙](./03-scope.md)과 충돌한다 | 데이터 요구사항 |
| U11 | **테이블 소유권 강제 방식** | (A) PostgreSQL 스키마 분리 (B) `public` 단일 + 명명 규칙 | (A)면 §4.3이 문서가 아니라 DB 권한으로 지켜진다. 초기 설정 반나절 | 전 영역 |
| U12 | **금액 절사·반올림 규칙** | (A) 절사(내림) (B) 반올림 (C) 절상 | **기획서에 없다.** 운임 80%가 정수로 안 나뉘는 경우(예: 3,333원 → 2,666.4원) 규칙이 없으면 대사가 1원 단위로 어긋난다 | `FR-B-03`, `FR-R-01` |

> **U12는 이 문서를 쓰면서 새로 발견한 공백이다.** 나머지는 팀 문서에 이미 🚧로 있던 항목이다. [대사(§6.2)](./05-functional-requirements.md)가 정산 합계와 원장 잔액을 비교하는 구조이므로,<br>
> 두 서버가 다른 반올림 규칙을 쓰면 **정상 동작인데도 대사가 실패한다.** 원장 담당자와 함께 정해야 한다.
