# 🚧 미확정 유스케이스 (UC-06 · UC-07)

두 유스케이스는 **08.15 회의 전까지 확정된 설계가 아니다.** 아래 내용을 확정된 것처럼 인용하지 않는다.

---

## UC-06 🚧 — 지급 완료 처리

| 항목 | 내용 |
|---|---|
| **주 Actor** | 관리자 |
| **보조 Actor** | 🚧 원장 서버 (`IF-03`) |
| **목적** | 확정된 정산을 지급 완료로 표시한다 |
| **관련 요구사항** | `FR-S-01`, `FR-S-02` 🚧, `FR-S-03` 🚧 |
| **상태** | 🚧 **미확정 (U7, U8)** — API로 노출할지, 배치 내부에서만 처리할지 결정되지 않았다 |

**미확정 쟁점**

| # | 쟁점 | 선택지 |
|---|---|---|
| U7 | 전이 방식 | (A) `POST /api/settlements/{id}/pay` 같은 API로 노출 (B) 배치 내부에서만 처리 |
| U8 | 원장 지급 분개 | (A) 기록한다 — 정산 → 원장 쓰기 호출이 생기고 실패 보상 문제가 정산에도 옮겨온다 (B) 기록하지 않는다 |

> **`PAID`는 실제 송금을 뜻하지 않는다.** 송금 연동은 범위 밖이다 ([기술서 §4.2](../01-requirements-statement/03-scope.md)). 발표·데모에서 이를 실제 지급으로 설명하지 않는다.
>
> (A)를 택하면 쓰기 호출이므로 `Idempotency-Key` 전파 규칙이 적용되고, 같은 키 재요청 시 재실행 없이 첫 결과를 반환해야 한다.

관련 다이어그램: [`SD-06`](../04-sequence-diagram/06-sd-06-payout-ledger-entry.md), [`FC-04`](../05-flow-chart/04-fc-04-state-transition.md)

## UC-07 🚧 — 정산 내역서 생성·보관

| 항목 | 내용 |
|---|---|
| **주 Actor** | 시스템 |
| **목적** | 정산 내역을 CSV/PDF로 만들어 감사 목적으로 장기 보관한다 |
| **관련 요구사항** | `FR-Q-03` 🚧 |
| **상태** | 🚧 **미확정 (U9)** — 보관 위치는 **DB 제품 결정에 종속된다** (Aurora면 S3, Supabase면 Supabase Storage). 또는 생성하지 않고 조회 API로 대체 |

> 우선순위 `C`다. `FR-B-08`(항목 단위 추적성)과 `FR-Q-01`(조회 API)만으로 [§3의 핵심 문제](../01-requirements-statement/02-problem.md)는 해결된다. 파일 생성은 그 위에 얹는 편의 기능이다.
