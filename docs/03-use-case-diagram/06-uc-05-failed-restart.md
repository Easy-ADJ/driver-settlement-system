# 🔄 UC-05 — 실패 배치 재시작

| 항목 | 내용 |
|---|---|
| **주 Actor** | 관리자 |
| **목적** | 실패한 정산을 처음부터가 아니라 실패 지점부터 다시 돌린다 |
| **관련 요구사항** | `FR-B-07` |
| **사전조건** | 해당 `targetDate` 배치가 `FAILED` 상태다 |
| **사후조건** | 남은 청크만 처리되어 배치가 완료된다 |

**주 흐름**

1. 관리자가 실패 원인을 확인한다 (로그 — `NFR-06`)
2. 관리자가 같은 `targetDate`로 Job을 재실행한다
3. Spring Batch가 메타 테이블을 참조해 실패 지점 이후만 처리한다
4. [`UC-01`](./02-uc-01-batch-execution.md)의 나머지 흐름을 따른다

**대안·예외 흐름**

| # | 분기점 | 처리 |
|---|---|---|
| E1 | 재실행 시에도 원인(예: 결제 서버 다운)이 그대로다 | 다시 `FAILED`. 원인 해소가 선행 조건 |
| E2 | 실패 원인이 데이터 문제여서 이전 청크 결과도 버려야 한다 | 🚧 미확정 — 배치 결과를 폐기하고 새로 돌리는 절차. `NFR-02`(항목 불변성)와 충돌하는 지점 |

> **E2는 짚어둘 만한 긴장이다.** `NFR-02`는 확정 항목을 수정·삭제하지 않는다고 규정하지만, `FAILED` 배치의 항목은 아직 확정된 것이 아니다. "확정 전 항목은 폐기 가능"이라는 예외를 명시할지 회의에서 확인한다.
