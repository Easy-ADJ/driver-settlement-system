# ⚖️ UC-02 — 정산 대사 검증

| 항목 | 내용 |
|---|---|
| **주 Actor** | 시스템 ([`UC-01`](./02-uc-01-batch-execution.md)이 include) |
| **보조 Actor** | 원장 서버 (`IF-02`) |
| **목적** | 정산이 계산한 금액이 원장의 장부와 일치함을 증명한다 |
| **관련 요구사항** | `FR-R-01`~`FR-R-04`, `NFR-03`, `NFR-04` |
| **사전조건** | 해당 배치의 `settlement_items` 저장이 완료됐다 |
| **사후조건** | 대사 결과(일치 / 불일치)가 판정되고 기록된다 |

**주 흐름**

1. 시스템이 해당 배치의 정산 항목 합계를 계산한다
2. 시스템이 원장 서버에서 기사 미지급금 잔액을 조회한다 (`IF-02`)
3. 시스템이 두 값을 비교한다
4. 일치하면 대사 통과로 기록한다

**대안·예외 흐름**

| # | 분기점 | 처리 |
|---|---|---|
| B1 | 3단계에서 불일치 | `RECONCILIATION_MISMATCH`. 🚧 통지 수단(U5)·확정 보류 여부(U6) 미확정 |
| B2 | 2단계에서 원장 서버 호출 실패 | 재시도 후 대사 불가 처리. 🚧 U6 |
| B3 | 절사·반올림 규칙 불일치로 1원 단위 차이 | **`FR-B-12`(U12)가 미해결이면 여기서 오탐이 난다.** 원장과 동일 규칙 합의가 선행 조건 |

> **B3은 이 유스케이스의 최대 위험이다.** 계산도 저장도 정상인데 대사만 실패하면, 원인을 찾는 데 가장 오래 걸린다.
